## 执行方式

1. 遵循当前需求与授权范围。“先出设计稿”止于设计，确认实现后再写代码。当前用户指令优先；实装与设计不一致时注明差异。
2. 查当前入口真实调用：战斗为 `GameBootstrap.ts`，现行商店为 `survival.ts`。`campaign.ts/CampaignView.ts` 保留旧商店和升级函数，不能误当现行流程。
3. 修改实现并做有行为意义的验证。正式试玩只用正常输入，不修改生命、金币、计时、敌兵或阶段；工程测试夹具与实际试玩分开报告。
4. **同一任务同步 skill**：更新受影响的人工参考，运行 `npm run skill:sync` 生成目录，再执行 `npm run skill:check`。`npm run check` 同时检查同步状态。
5. 按修改范围执行测试、类型检查、构建；交付明确是否已加载微信端，不把模拟器检查说成手机验证。

生成器不会审批新规则，也不会自动重写人工说明。不要只刷新目录便宣称全部参考已更新；目录描述不等于最终运行时效果。发现实现差异先记录，不在无关任务中擅自改玩法。
