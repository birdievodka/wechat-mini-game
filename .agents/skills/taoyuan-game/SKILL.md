# 桃园小英雄项目 skill

这是随代码维护的项目约定。仓库根目录包含 `assets/scripts/GameBootstrap.ts`；通过用户级软链接调用时，先定位实际仓库，不在 skill 安装目录构建游戏。

## 当前主线

- 正式名称“桃园小英雄”（原名桃园乱斗）。展示名称由game-brand.ts统一定义；菜单使用独立新Logo，不再显示旧atlas里的旧名。保留AppID、taoyuan存档键和技能目录名以兼容历史进度。

- 搞笑三国、小脚豆Q版，突出头部和手臂；横屏移动、自动攻击。
- 当前AppID手机预览上限20MB，发布包安全预算19MiB；PNG原图存art，运行贴图压缩后保留尺寸和精确alpha。
- 左下固定方向摇杆，右下携带的通用技能；五英雄基础移速300/295/290/325/285，轻推响应曲线0.8；电脑保留方向键/WASD。
- 启动与Loading统一使用刘关张战斗海报和连续进度条，不显示默认Cocos启动标识；完成关键资源后才进入选人。
- 首页无“选择英雄”标题、独立桃园演武场（不复用Loading海报、无纸色圆盘）、上方单个分层动态英雄展示、下方五个纯头像选择位、列表右边仅显示图标的小技能按钮和底部水平居中的“开始”，没有属性条、等级或初始武器选择页；右下新增独立“演武场”入口。
- 演武场可配置40小兵/17场Boss与数量、36武器四品级六槽、24主动技能；主角无限生命，手动出兵、技能就绪和清场，不写正式存档或推进章节，详见training参考。
- 首页“开始”始终使用当前所选英雄/技能开启第1章新局，重置金币、构筑、五心与计时；不读取旧快照、不弹“继续征程/新征程”。章内死亡“重试本章”及暂停恢复保留。
- 默认刘备草鞋、关羽扁担、张飞杀猪尖刀、赵云龙胆银枪、孔明白羽扇。15秒第零章后**先补给**，首轮收入补足到28金币，保证能买一把新武器；点“继续战斗”原地衔接正式战斗；不自动送武器。
- 已移除英雄专属主动技能：24通用技能全英雄自由选1个，开局就绪，释放后靠击杀小兵重置；时间不充能，动物/桃树/Boss/召唤物不计。强力技能需更多击杀；后续解锁仅预留接口，本轮全部开放。
- 横扫六合已按确认的A金锋回旋实装：金白厚刃月牙、双层拖尾、真实命中火花和短暂拧身回正，仍半径250/最多10敌一次，不能恢复成细环加六箭头。
- 其余23通用技能已按确认方案接入`skill-vfx-art.ts`与真实Runtime事件：云履、回刺、青锋、玉滴、纸衣/鼓偶、双盾、战旌、破釜、三纸弩兵、苇帆、卷焰/白沫潮、龟甲/八門、桃心、虎颚、断锋、四雷、四旌、赤羽箭与五曜。机制、充能与原生命周期保持；G03 A版不重做，详见common-skills与combat-effects。
- 正式模式五颗心，普通伤害一次一心；过关保护与真实受击反馈分开。
- 购物冻结战斗但BGM持续播放；隐藏全部战斗HUD/暂停/摇杆/技能键，保留战场。玉绿补给面板采用顶栏余额、三商品、六武器与道具同组、底行刷新/继续战斗；替换/出售/合成/背包同主题，替换先选旧武器、显示净额且确认前不成交。切后台暂停，回到商店接续。
- 六武器位；道具不占位，可无限叠加但收益递减。每屏三件可全买，刷新后还能买，刷新费逐次增加。
- 多武器环绕分布，不挤在手上；飞剑为持续旋转、接触伤害的剑阵。
- 密集战斗使用共享粒子四边形与启动烘焙弹体/金币/出生效果图集，避免逐对象Graphics大缓冲；280粒子与危险特效、伤害判定保持。
- 36武器UI使用统一手绘图标；英雄头袍分层、真实眨眼与各自待机小动作，不能只用整图旋转。
- 手臂为低位短弯袖、独立圆手掌；袖子在头后、手掌在武器前，多武器仍只有两只自然手。
- 地图宽高各为视野1.5倍，草地小花为主，小桃树可击倒掉桃回血。
- 六卷17章，每章15秒第零段＋三波各30秒＋Boss；首领加入时保留小兵/弹幕并持续援军。章末回1心，章间补给、装备继承；最终司马懿·五丈原才通关。张角只为首章。
- 40类敌兵、14人物/17次首领战、36武器、60被动和9天命。固定章节HP/成本预算，不按玩家装备加血；移速涨幅封顶，预告与弹速不随章节加快。
- 首页图鉴包含兵种/首领、四品级武器、24通用技能；本轮24项全部开放，选人自由携带1个，按综合威力升序，击杀真实小兵充能。schema4存整备点与交易货架，死亡重试本章入口、不保留失败所得；没有经验和隐藏等级成长。
- 失败结算使用五英雄专用哭泣图、右侧战报纸卡；失败主按钮“重试本章”、通关“再来一局”；不能继续使用战斗笑脸；通关必须开心立绘和“胜”章。

最新用户指令可以修改这些规则，完成变更后同步本 skill。不要用旧八关/60秒、旧选武器流程或历史设计稿覆盖当前实装。

## 执行方式

1. 遵循当前需求与授权范围。“先出设计稿”止于设计，确认实现后再写代码。当前用户指令优先；实装与设计不一致时注明差异。
2. 查当前入口真实调用：战斗为 `GameBootstrap.ts`，现行商店为 `survival.ts`。`campaign.ts/CampaignView.ts` 保留旧商店和升级函数，不能误当现行流程。
3. 修改实现并做有行为意义的验证。正式试玩只用正常输入，不修改生命、金币、计时、敌兵或阶段；工程测试夹具与实际试玩分开报告。
4. **同一任务同步 skill**：更新受影响的人工参考，运行 `npm run skill:sync` 生成目录，再执行 `npm run skill:check`。`npm run check` 同时检查同步状态。
5. 按修改范围执行测试、类型检查、构建；交付明确是否已加载微信端，不把模拟器检查说成手机验证。

生成器不会审批新规则，也不会自动重写人工说明。不要只刷新目录便宣称全部参考已更新；目录描述不等于最终运行时效果。发现实现差异先记录，不在无关任务中擅自改玩法。
