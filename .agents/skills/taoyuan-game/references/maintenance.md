# 后续维护

用户要求这套 skill 与项目一起更新；这是本项目的交付要求。当前用户提出新规则时应更新规范，而不是用规范拒绝变更。

`cocos-game-vfx`是仓库内独立的特效工作流skill，入口由根AGENTS与主skill关联。特效的通用流程和代码适配变化在该skill维护，具体当前数值/表现仍在本skill的战斗特效和通用技能参考维护。目录扫描覆盖`.agents/skills`下全部skill；新skill无需手工加入文件白名单。

## 哪些文件跟着变

| 变更 | 人工参考 | 自动输出 |
| --- | --- | --- |
| 阶段、生命、经验、掉落、敌军、地图 | `gameplay.md`，必要时 `known-gaps.md` | 数值表、机器目录、来源指纹 |
| 武器、道具、交易或平衡 | `weapons-items.md`、四品级行为改动同步`weapon-evolution.md`，必要时玩法/已知差异 | 武器全表、道具全表、数值表、机器目录 |
| 角色造型、UI、特效、音效、素材布局 | `art-ui-audio.md`；战斗粒子同步 `combat-effects.md` | 资源清单、声音路由、粒子/摇杆常量、来源指纹 |
| 武器图标、战斗分层角色、待机/眨眼 | `presentation-animation.md`、美术/启动/工程参考 | 裁格素材、版本、启动任务及来源指纹 |
| 构建、版本、包预算、控制/验证方式 | `engineering.md` | 配置、版本和来源指纹 |
| 启动海报、默认标识、加载进度、就绪门槛 | `startup-loading.md`、必要时美术/工程参考 | 启动任务表、模板与来源指纹 |
| 结算页、哭泣表情、成绩/重开流程 | `result-screen.md`、必要时美术/启动参考 | 表情素材、启动任务及来源指纹 |
| 解决具体描述/实装缺口 | 删除/改写 `known-gaps.md` 对应事实，补相关参考 | 重新生成受影响条目 |
| 纯问答/阅读/试玩，无仓库变化 | 无需更新 | 不需要伪造更新 |

## 命令

在仓库根运行：

```bash
npm run skill:sync
npm run skill:check
npm run check
```

`scripts/sync-catalog.cjs` 是本 skill 的确定性生成器：加载纯TypeScript规则，生成 `catalog.json`、`weapon-catalog.md`、`item-catalog.md`、`balance-tables.md`。它不启动Cocos、不改游戏、不请求网络、不调用云文档。

源扫描覆盖当前源码、实际素材与meta、构建/校验脚本、配置、AGENTS及人工skill参考。新增文件也会被扫描，art下所有保留资源统一纳入，不能继续维护过期版本白名单。纯数值/目录来自导出对象和实际计算函数；状态流程和画风由人工说明维护。

`--check` 只读，对比应有输出与现有文件，发现过期返回非零并提示同步。`npm run check` 接入该检查。输出没有生成时间戳，重复同步应无差异。

可选 `--project /path/to/repo` 指定仓库，`--output-dir /tmp/skill-fixture` 把生成结果写到隔离目录，供验证/迁移；正常维护使用默认位置。机器目录中的素材字节是源码素材量，不是最终微信包大小，发布包仍由构建检查。

## 一次变更如何收尾

1. 依据本次最新需求修改代码/设计，确认实际入口，不只改旧兼容函数。
2. 更新受影响人工说明，删除已失效规则；需要时同步SKILL入口的“当前主线”、README与实现记录。
3. 运行生成器，再检查目录准确性。新增武器/被动不应只出现在设计文案，也要在实际路由/适配/交易和生成目录出现。
4. 做与改动相称的验证，再跑同步检查。修改skill本身可用系统 `skill-creator/scripts/quick_validate.py` 检查结构，同时检查相对链接与资源可定位。
5. 交付说明skill已同步、游戏是否构建/加载、还有哪些具体未验证部分。

不要手改生成表作为数值源，不要只更新哈希而不审阅人工说明；也不为凑更新而重复生成图片、重写历史文档或重跑无关检查。

## 目录与已知差异

目录含原始定义、首次/重复叠加后的派生字段与适配条件；它不能证明某字段被消费。例如 `stipend` 有数值但现行发钱路径可能没用。优先用可观察的付款、增兵、伤害、触发次数、位置等行为测试，不能只测配置对象改变。

用户要求资源只保留最新版本。当前源图与生成依赖必须保留；失效候选、重复评审导出和过期取证删除，历史通过Git追溯。具体分类与执行边界见[资源维护](resources.md)。不要自动向飞书、邮件或外部服务同步，除非用户另有要求。
