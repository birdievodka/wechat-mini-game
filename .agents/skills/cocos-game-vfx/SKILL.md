# Cocos 战斗特效设计与实现

把可辨认的视觉方案落到真实战斗调用链，而不是只交概念图、孤立绘制函数或更亮的圆环。适用于Cocos Creator二维战斗，微信小游戏优先；项目的画风、引擎版本和当前用户要求决定具体实现，不把案例数值推广到其他技能。

## 先识别工作范围

- **只设计或出几张图**：交付同一战场尺度的候选方案和关键阶段，标注为概念；不改战斗。
- **按已选方案实现**：读取已确认图与真实代码，直接实施、验证和构建；已有授权不再增加确认环节。
- **设计完成后直接实现**：在本轮完成两部分；不能把内部方案完成当作停止点。
- **盘点当前特效**：从实际入口、机制与绘制取证，区分当前效果和建议方案。

## 从设计到实现

1. **先查真实入口**：找到施法/出手、实际命中、表现控制器、前后层、暂停与清场。定义文件写了效果，不代表运行时已接通。
2. **分开记录机制和视觉**：机制包括范围、命中时刻、目标/次数上限、伤害、控制、充能；视觉包括主形状、色彩、阶段、层级、命中反馈和预算。只升级表现时保持机制契约。
3. **以轮廓和动作建立身份**：主形状、明暗边缘、方向、节奏、真实接触反馈优先；粒子是辅层。相邻技能不能只换颜色。用实际手机显示尺寸看清人物脸、敌兵和危险边界。
4. **选择合适载体**：简单连续形状可用共享Graphics/预计算几何；大量重复物用缓存贴图/Sprite；手绘纹理或新位图概念使用可用的imagegen能力。无需为展示原型引入新渲染框架或为每个粒子建Graphics。
5. **接入真实时钟和事件**：模拟更新生命周期，绘制只读。命中火花来自确认的命中，不能固定撒在圆周；空放不触发命中。角色动作使用表现层偏移，不能意外改位置、朝向或武器碰撞。
6. **检验方案还原程度**：比较同尺度概念和真实战场的起手、峰值、收尾。检查刃面厚度、拖尾间隙、颜色、前后遮挡；发现仍偏细或混入旧色，修对应层，不能仅加亮度。
7. **按范围收尾**：完成行为/资源/压力检查；需要运行体验则重建并核对真实运行版本。同步项目skill、案例引用及来源记录，报告实际证据和未测范围。

## 必须保持的边界

- 表现帧不决定伤害；绘制、裁剪、粒子发射失败或池满不能改变命中和掉落。
- 视觉随机数与战斗随机数隔离；不因增加碎屑改变暴击、出兵或收益。
- 时间与空间语义一致：世界坐标/局部坐标、瞬发/扩散、固定/跟随、攻击范围/装饰余波须明确。
- 友方效果不遮住敌方危险提示；不用全屏白闪掩盖人物动作。后层与前层衔接检查几何和透明度，避免硬接缝。
- 所有临时任务、姿态、声音和粒子按项目的暂停/后台/商店/重开/销毁规则收回；效果不能在绘制时自行计时或重复发射。
- 概念图、程序定帧、真实模拟器关键帧合成、连续录像与手机实测分别标注；不能互相代称。
- 不自动上传文档或修改外部资源。若用户本次指定飞书等交付位置，再使用对应能力。

## 桃园项目的只读入口

从任意目录运行，`--project` 指向实际仓库；未传时从当前目录向上定位：

```bash
node /path/to/cocos-game-vfx/scripts/inspect-taoyuan.cjs --project /path/to/project --skill G03
```

输出当前技能定义、实际预算常量、集成定位、案例路径和源码哈希；不启动Cocos、不改存档、不构建、不调用微信。只读检查不能替代行为测试或运行画面。

## 给实施agent的交接

提供项目根目录、目标ID、用户已选方案/授权范围、机制契约、实际调用链、关键阶段及层级、预算、参考图/代码、验证入口。使用[设计说明中的交接模板](references/design.md#交接模板)，具体缺口可依据现有代码解决；只有会改变用户意图的缺口才询问。
