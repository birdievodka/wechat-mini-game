# 代码落地

## 按真实调用链接入

先定位定义、Runtime、表现控制器、绘制和实际组件。一个函数在测试里能画出来，不等于游戏正在调用。只改绘制函数时检查调用参数、生命周期、图层与缓存是否仍使用旧版本。

在《桃园乱斗》中，读项目适配说明后，沿以下路径查找：

```text
chronicles-data / common-skills
  → GameBootstrap.castSkill
  → CommonSkillRuntime.cast / update / hit
  → CommonSkillEffects.play / update / draw
  → sweep-effects等纯绘制模块、combatFx、ParticleSprites
  → GameBootstrap.updateEffects
```

这是案例路径，不要求其他仓库新建同名文件。优先复用现有系统。

## 分离机制、事件和表现

- **Runtime**负责真实命中、有效目标、伤害与次数去重、保护/控制和延迟任务。
- **事件**记录施法源点、锁定或跟随语义、朝向、半径、持续时间和实际接触点；不要每次draw重新索敌。
- **Effects**负责有限槽位、age/life、粒子发射、消失与裁剪；不反向调用伤害。
- **draw**只消费现有状态；多画一次不能新增粒子、推进计时、改变随机数或触发命中。
- **角色表现**合成在已有行走/待机之后，并在收尾归零；不写玩家位置和真实碰撞朝向。

命中闪要绑定已接受的伤害事件，不能仅凭“敌人位于附近”创建。现有Host如果不返回命中结果，查看真实伤害入口会不会拒绝/延迟结算，再选择该入口的回调或确认状态；不要凭接口名称推断已命中。替身、出生期、尸体和中立物按当前机制过滤。

时间上的起手、主效果与命中也须对齐。若当前为瞬发，不擅自插入可影响手感的长等待；若当前有延迟落雷/陨星，预表现先出现，落地时才伤害。

## 载体选择

| 表现需求 | 优先考虑 | 需要核对 |
| --- | --- | --- |
| 少量月牙、扇刃、雷叉、边缘线 | 共享Graphics、预计算轮廓/几何 | 凹多边形、接缝、顶点量、每帧分配 |
| 大量相同火花、金币、箭与弹体 | 同图集Sprite或已有粒子四边形 | alpha紧裁、共享材质、池复用、旋转锚点 |
| 手绘火焰、烟、笔触、复杂帧动画 | 小型透明贴图/序列图集 | 解码内存、尺寸、阶段对齐、真实alpha、加载完成门槛 |
| 更复杂的变形或材质 | 当前引擎支持的mesh/shader | 当前平台能力、裁剪模块、回退与包成本 |

不要为简单刀光引入一套独立引擎、后处理或渲染框架。项目已有程序图形可直接扩展；需要新的位图时使用imagegen等适当工具，不用临时代码假装手绘素材。

## 月牙不是圆环

横扫案例采用外沿与内沿构成带厚度、首尾收尖的实体轮廓；角向宽度曲线决定哪段最厚。背沿、实体刃、暖白刃面和细锋分层，拖尾用偏移的较小/较淡轮廓；短笔触保留间隙。优先检查手机尺度的实际厚度，不能只在大画布上好看。

后侧与前侧沿同一轮廓分段投到不同层。边界端点、宽度和alpha要相同，否则出现直切边或亮度硬缝。不要为了表现透视把真实圆形判定随意画成窄椭圆；投影应与游戏的坐标/相机规则一致。

实现示例看当前项目的 `assets/scripts/sweep-effects.ts`：

- 单位弧样本在模块初始化时生成，不在每帧重新创建坐标数组。
- 用共享TypedArray暂存旋转后的外沿/内沿坐标，填充实体月牙。
- `drawGoldenSweep`只绘制；`drawSweepContact`只处理真实接触事件的局部形状。
- 同alpha前后层衔接、逐段收尖、短笔触与有限淡出，比加大白闪更重要。

共享可写暂存区要求绘制同步且不重入。若项目并行/异步生成mesh，使用实例缓冲或受控池，不能直接复制全局数组方案。

## 命中和角色反馈

主效果之外，组合现有受击闪白/压扁、定向接触楔形、向外碎屑、阻尼击退和短音效。先复用项目已确认的反馈；不因视觉任务增加硬直、免伤、额外击退或伤害段数。

检查通用命中系统是否叠加了不合适的颜色。横扫第一轮仍混入旧青色金属火花，最终改用已有暖白金属命中样式；更换样式ID前须检查它是否还参与护甲、武器专属加成或连锁，不能假设仅影响外观。

动作偏移可驱动躯干转动、轻压身、头部反向小摆、自然手腕。与移动/待机/受击合成后及时归零，不旋转或改写整个玩家碰撞实体，不生成第三只手。镜头微震只作用世界层，不能带动HUD或改触摸坐标。

音效沿用项目声道、同帧限频与用户手势解锁机制；不要每次命中构造新AudioSource，也不要为了补视觉重置BGM。

## 生命周期与预算

从当前代码获取池容量，而非把横扫案例的280/32/36视为Cocos通用限制。考虑同一时间主体、每个接触点、拖尾和原武器粒子的总量。粒子满载只影响装饰，伤害和控制继续正确结算。

- 预计算静态轮廓、缓存颜色/材质/贴图；避免帧循环中反复new Color、数组和节点。
- 复用图层；本项目已证实每对象Graphics有较大的固定缓冲成本，不能为每个碎屑创建它。
- 贴图内存按解码RGBA等估算，不能拿PNG文件体积替代；控制透明大四边形造成的过度绘制。
- 帧模拟推进age，帧绘制只读；暂停/商店/后台不发射、不衰减，按项目规定恢复。
- 到期、重开、切章、死亡与销毁均清状态，含任务、姿态、Sprite、监听和纹理引用。
- 视觉随机数独立；裁掉屏外表现不应推进游戏随机序列或改变攻击。

这些是实施边界，不自动授权减少已有敌人数、粒子预算、分辨率或玩法复杂度。
