# 设计与交接说明

## 先看什么

读取当前角色、地面、敌兵和待改效果的实际图，确认人物头宽、世界范围、镜头缩放、遮挡与平台显示尺寸。不要只看放大海报；只有小尺寸仍成立的形状才适合密集战斗。

对已有技能先说明它为何不清楚：没有实体刃面、主次均匀、没有方向、主效果和命中反馈混色、缺少角色配合，或几种技能形状重复。把问题落到可观察的变化，避免只写“更华丽”。

## 形成有区别的候选

用户要几版时，比较的是视觉身份，而非同一圆环的颜色：厚刃旋扫、错位分段刃、干笔墨金等可形成不同方向。它们仍遵守同一机制，装饰六段不等于六次伤害。已有方案获准实现时无需重新开展一轮选型。

每版至少表达以下关系，详细程度随任务调整：

- 主形状和方向：刃锋、火柱、雷叉、船帆、纸兵等，缩到游戏尺寸仍可辨认。
- 明暗和材料：例如暖白锋面、金色实体、赭色背沿，而非无限叠加发光圆。
- 起手、爆发、收尾：最亮和最实的形状只持续短段，余波迅速让出战场。
- 角色配合：拧身、压身、反向摆头、手腕或武器随动，保持现有解剖和动作驱动。
- 真实接触：敌人闪白/形变/击退、接触楔形、短碎屑、合适音效。空挥不能出现打中敌人的反馈。
- 空间层级：地面痕迹、后侧弧、人物、前侧弧、接触碎屑、敌方危险提示。

时长由现有机制和手感决定。横扫六合当前0.4秒只是项目案例；不能把所有技能都压成0.4秒，也不能为了画蓄势而擅自延后瞬发伤害。

## 图的真实性

| 类型 | 用途 | 交付时说明 |
| --- | --- | --- |
| imagegen概念图 | 比较美术方向与视觉身份 | 不是实装、真实截图、可直接播放的素材或性能证据 |
| 程序绘制定帧 | 观察真实绘制代码的形状、颜色和范围 | 模拟场景、绘制适配器与真实Cocos可能不同 |
| 微信/Cocos截图与关键帧合成 | 核对真实引擎层级、尺寸、效果阶段 | 关键帧合成不是连续录屏；工程布景不是正常通关 |
| 原设备录屏与测量 | 核对实际操作、连续动画和性能 | 标明设备、场景、负载与采样范围 |

选定概念原图保存到项目的非运行目录，保留提示词与来源。只有被运行时实际消费的素材才进入assets并配置meta/分包；不要把整张效果海报直接打进小游戏。

## 生成位图概念时的提示词

按当前工具的imagegen skill调用，参考图明确用途，生成后检查，不把下面模板当作固定引擎API：

```text
用途：现有二维战斗游戏的技能特效概念稿。
参考图1：真实战场的画风、尺寸和镜头参考。
参考图2：现有效果的改进对象，不沿用其已指出的问题。
参考图3：人物造型参考，只使用指定角色。
技能：名称、现有空间范围、固定或跟随、伤害时点。
主形状：轮廓、材料、方向、首尾收尖、需要可见的间隙。
层次：主效果、拖尾、接触反馈、地面碎屑及角色动作。
构图：同一游戏尺度的大场景，加起手/峰值/收尾小图。
保持：项目人物比例、现有敌兵、地面、脸部留白、危险提示可见。
边界：装饰不代表额外命中，伤害范围外不表现受击；禁止全屏蒙白。
文字：只使用指定的少量标题或阶段名；不烘焙交互控件。
```

不要在尚未看到生成结果时宣称已还原方案；不要让生产素材只有概念图里的白背景或假透明棋盘格。

## 交接模板

这是工作说明模板，不是必须新增文件；可以直接写入实施任务或已有策划文档。

```text
目标与授权
项目根目录；目标技能/武器ID；只设计或设计并实现；已选方案与图路径。

机制契约
当前定义和真实施法/命中入口；世界单位；位置锚点与朝向；命中时刻；
范围；伤害与目标/次数上限；控制/击退；充能；哪些允许变化。

视觉方案
主轮廓、配色与材料；关键阶段和总时长；后层/前层/危险提示顺序；
角色表现偏移；命中/空放差异；可见范围和装饰范围的区别。

实现映射
定义模块→Runtime事件→Effects生命周期→绘制/缓存层；
真实命中回调；姿态合成点；暂停/清场/销毁；音效复用；资源加载和失败回退。

预算
从代码读取的池上限、单次额外实例、顶点/贴图解码成本、包预算。
哪些是实测，哪些待测。

验收
范围内/外、空放、目标上限、不重复、只读绘制、回收与暂停；
关键帧/真实模拟器/设备体验入口；构建版本；需要同步的文档和skill。
```
