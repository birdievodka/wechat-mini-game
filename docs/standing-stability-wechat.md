# 百万生命站桩逐关实测（微信开发者工具）

版本：`stage-v9.15-session-audio`。用户明确要求生命1000000、站着不动、逐关观察。2026-11-18在macOS微信开发者工具真实小游戏运行时执行；不是浏览器替代、不是iPhone实机测试。

**六关自然通关，1510秒（25分10秒）完成；持续采样/恢复前观察1524秒（25分24秒）。战斗期间未复现退出。**

## 测试方式

- 小张从第一关/白I杀猪尖刀/初始横扫六合开始，临时测试档从零解锁。每关新构筑按生产规则清空，成长正常派生。
- 生命上限/入关生命临时设1000000；真实受击扣血、红闪、击退均保留，观察到720点净下降采样。每关中Boss回血不能把测试生命误夹回原6–12心。
- 没有方向输入，所有快照keys=0、摇杆x/y=0；受击击退产生位置变化。技能只在真实15小兵击杀充满后释放，不改充能。
- 商店自动按真实金币消费，优先武器/升阶，最多两次付费刷新；未送金币或装备。实际178次购买、143次主动释放。
- 不改敌兵血量/伤害/出兵频率，不加速、不推进时间、不手动置通关或击杀Boss。只以真实Boss死亡过关，经过实际结算/菜单/下一关准备。
- 原始g.update渲染驱动，每20秒外部读样本；从未调用simulate或director.tick加速。测试中微信构建/资源版本未改，包含完整三国六主题和七Boss自然流程。

## 额外观察与边界

1. 返回原选人页后成功读取：正常生命上限5、当前5；currentStats/update没有测试覆盖，临时计时器已关，全部taoyuan存储与原始快照逐键恢复。主代码和构建没有写入百万生命。
2. 恢复后的菜单快照仍有较高固定绘图占用：buffer 121.58 MiB、texture 92.32 MiB，合计213.91 MiB。需要进一步按绘图模型区分菜单和战斗池高水位；这里不把单个较高快照称作泄漏。下一步可优先审查返回备战时的战斗Graphics缓存回收。
3. 正常恢复与5心核验成功后，再次追加查询时项目窗口/运行时已不可用；工具主进程、Mac微信主进程仍在，没有看到本机系统崩溃报告。原因未确定，不默认为游戏崩溃，也不把这条后置CLI错误计作战斗期脚本异常。原始错误单独保存。
4. 25分钟未复现不能证明已修复原iPhone15 Pro Max整微信退出。这里没有iOS进程RSS、JetsamEvent或手机原生崩溃栈；若原机仍退出，需结合对应时间系统日志区分内存终止、原生音频或其他原因。
