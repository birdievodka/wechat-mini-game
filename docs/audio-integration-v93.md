# v9.3 游戏内音频试听

用户已要求直接接入游戏试听，本版为`stage-v9.3-audio`。原始试听页仍保留素材出处与离线混音；实际游戏使用经过分事件处理的小体积副本。未改变伤害、攻速、敌军数量、主动技能15击杀规则或存档。

## 声道、包和内存

六个固定音效AudioSource＋一个复用音乐AudioSource。普通出手优先0、敌方出手1、命中2、技能/交易3、受伤/格挡/危险4；低优先不能挤掉高优先。每个cue有同音限频，群伤按攻击事件响，钱币/死亡/出生按时间合并。重要战斗反馈短压低音乐约6dB，约220ms回升，普通连射不反复压音乐。

音乐按当前场景加载，离开时先停止并解除clip引用，再释放上一首解码资源；世代号处理“加载中切场”和退出竞态。没有一次解码三首，也没有双源交叉淡化。音乐64kbps AAC、24kHz单声道，三首约1MiB；86段新音效为24kHz单声道PCM，原草鞋逐字节保留，实际87声源。微信最终构建总包19.00MiB，音乐分包1.01MiB、音效分包1.63MiB，仍低于本项目19.5MiB安全线与各包4MiB检查线；最终以重建日志为准。

源：`art/audio/review-v1/manifest.json`及音序。采纳：`art/audio/runtime-manifest.json`。`scripts/pack-game-audio.py`生成实际资源和`assets/scripts/audio-catalog.ts`，再由`weapon-sound`与GameBootstrap消费。86不是86种独立乐器录音，类别和技能有意共用音色。旧运行WAV音乐和10个兼容音效已移除，历史仍可由Git追溯。

## 验证边界

- `test-audio-scenes`：菜单时钟、购物不重播、后台迟到下载、旧解码clip释放；8/4/5/4真实技能时序、取消无未来声音、受伤声道优先。
- `test-music`：手势、独立开关、淡入、暂停、迟到/退出竞态、40/60/30秒逻辑时钟、压低/恢复、AAC文件预算。
- `test-weapon-sound`与组件回归：文件端点/无静音/峰值、分类路由、草鞋无风声、群伤/穿透只响一次、音效静音。全部游戏测试、typecheck/check和微信重建随本次完成。
- 微信运行时检查版本与已载音乐/声源；实际引擎播放状态与手机主观听感分开报告。AAC宿主报告时长含约0.1秒编码余量，母带是40/60/30秒；手机循环接点和最终响度需要用户试听，不能把Node计时测试说成真机无缝验证。

试听优先走“选人→开战→演武任意武器/技能/Boss→购物→受伤→后台返回”。若未出声，可先点选一个英雄以解锁音频，再查看暂停页“音乐／音效”是否开启；不会替用户强改已保存的静音偏好。


真实引擎验收：`scripts/capture-audio-review.mjs`在独立Chrome/Cocos实例中，通过实际鼠标点选英雄/开始、键盘施法，再用受控受击/购物/切曲夹具验证。备战.65、战斗.72、首领.72，均playing=true且播放时钟递增；购物接续原battle，后台停、前台恢复、返回menu正确。受伤与实际G01均收到AudioSource STARTED，87声源/6效果播放源，运行异常0。数据在`art/reviews/audio-v93/validation.json`。微信工具确认stage-v9.3-audio及87声源已加载；当前模拟器未连续绘帧，未宣称已在微信画面完成音频听感验收。预览二维码生成成功，工具报告源码19,895,083 bytes。iPhone最终听感仍交用户试听。
