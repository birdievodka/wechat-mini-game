# v9.13 审查报告落实：加载、生命周期与稳定性

审查输入：《桃园小英雄-性能稳定性审查.md》，基线 f8104be / stage-v9.12-stability。本次逐项核对源码，采用已证实的问题及能够保持战斗结果的优化。运行版本为 `stage-v9.13-lifecycle`。没有原 iPhone 系统终止日志，不把资源管理缺口等同于原机闪退的唯一原因。

## 已落地

| 报告项 | 处理与边界 |
| --- | --- |
| R1 加载无截止 | `load-lifetime` / `AssetScope`覆盖核心Bundle、纹理、农兵二进制与解码、海报、兼容图、可选美术。普通阶段真实时间18秒，Boss/延迟图整组20秒，音效30秒，音乐整笔18秒；多阶段首屏有各阶段截止，不能宣传整个首屏固定18秒。暂停不冻结截止；关键失败不假就绪，准备页可重试/返回，可选失败保留既有画面。 |
| R2 音频挂起 | 原草鞋进入相同的限时、去重、退避队列；所有任务另有30秒watchdog。音乐切场立即取消旧世代，不等旧回调；超时可退避再试，迟到Bundle不启动后续解码，不补播过期命中。析构撤销计时器及排队任务。 |
| R3 原生失败回退 | 微信与浏览器明确分流。微信初始化失败保留URL缓存、释放失败池，每30秒最多重建一次；不创建六个Cocos音效源，不回到全音色AudioClip常驻。浏览器保留Cocos音源。正常六声道、优先级、限频和BGM不变。 |
| R4 美术到达重置攻击 | arsenal回调改`refreshWeaponArt`：只更新原Sprite外观，不调用战斗更新或重建剑阵。装备同步按槽位身份跳过未改变装备；重开/清场明确失效。计时、冷却、命中集合、连击与剑阵previous保持。 |
| R5 资源所有权 | 每场景和临时发布事务用`AssetScope`租约；加载资产addRef/decRef，程序纹理仍destroy。旧请求结果在新请求发布期间有临时身份保护，多旧回调同纹理只持一份保护。最后无人持有的AudioClip元数据立即安全释放，避免同步缓存加载全挤到下一引擎tick；音乐和其他持有者仍受引用保护。不用releaseAll或只凭帧表强制销毁共享资源。析构先解除子树Sprite引用、去重销毁含rigFrames的派生帧、销毁自己创建的Canvas，再释放租约；任一清理项抛错不阻断其余项。 |
| R6 诊断风暴 | 同类事件合并首条/末条/次数，最多8类。严重类别首条及时落盘，其后限频、批量flush；存储配额异常同样限频。每个on/off监听独立隔离，只注销注册成功项，后台/退出flush。原本地单层previous和无上传边界保持。 |
| R7 尸体池 | 保留先复用完全退休槽的原顺序；没有空槽时再复用已不可见的1.15秒尾部。演武配置明确新增目标前退休死槽，防暂停配置反复扩池；连续100次生成/击杀夹具保持80槽。正常可见死亡动画保留。此为实际复用路径修复，**未宣称任意违规注入都具有总分配硬上限**，也未以丢兵实现容量限制。 |
| R8 CPU热点 | 软分离复用活体列表，保持原配对顺序，并在每对处理时读取实时位置；不使用可能漏掉新邻居的静态网格。连续椭圆碰撞增加相对运动扫掠AABB保守筛选，原二次窄相和接触排序不变。30,000组差分保持完全相同TOI。完整空间网格、全量统计缓存另做差分/设备计量，未盲目合入。 |
| R9 模块兵dirty写入 | 9个Sprite直接设置最终可见性/袖色，器械不先激活再隐藏六部件；锚点、尺寸、色、角度、位置按值缓存。动作仍每显示帧采样，不删手臂、不减动作帧。重复站姿100次锚点/尺寸/可见性重复写入为0。 |
| R10 空图层 | 仅四个共享FX层跟踪路径/fill/stroke；空→空跳过底层clear，最后有内容的一帧清一次，其他动态形状照常绘制。600次空clear无实际clear；内容结束只清一次。没有把所有静态UI重写，也没有虚报每个隐藏Graphics的GPU节省。 |
| R11 非有限数 | 主update在布局、声音和模拟前检查delta，连续三次异常安全暂停；异常主角坐标安全暂停、恢复为有限值。声音、音乐、通用技能与独立simulate入口也拒绝非有限delta；菜单展示步长有界，正常1/120子步、.08帧预算和CCD保持。 |
| R12 合并与订阅 | ResourceGate逐订阅隔离；Boss复用完整sheet事务，孟获并发准备只提交两张图，不生成两组帧；Boss/隐藏英雄/战报组的alive和done逐项隔离，取消不影响其他有效订阅。所有图齐备后才发布。 |

P3同时处理：坏档按合法ID过滤、去重和128KiB输入上限；首次发现200毫秒批量保存，后台、失败、菜单、通关与退出可靠flush；BossEffects同名key也检查SpriteFrame身份。没有为拆类而改写玩法主循环。

## 验证口径

- `test-review-stability.cjs`：永不回调/超时/重复/同步throw/重试、旧新同纹理交错、多个迟到同身份回调、订阅者抛错、孟获整组去重、原生初始化失败与恢复、66段同步音效元数据及时释放、挂起草鞋/音乐连切、万次错误及存储异常限频、析构失败隔离、六剑外观迟到不动战斗状态、演武100轮、模块兵静态属性缓存、空层、非有限帧、三万CCD差分、坏档限界。
- 现有全回归与类型检查通过，最后的退出/诊断边界另做专项回归；少年美术保护仍锁定原Boss绘图，仅允许同名帧身份失效修复，未刷新美术基线掩盖改图。
- `diagnose-review-lifecycle.mjs`为独立loopback/独立Chrome目录的真实Cocos/WebGL工程夹具，100次菜单→战斗→商店→菜单，20次场景/组件析构，等待真实销毁后量GPU和资源数；带恢复和watchdog，不连接微信玩家对局。不把桌面GPU计数当iOS总RSS或手机FPS。
- 另用80混合兵、实际预载首领与六件IV武器的真实GPU提交测试确认核心战斗表现/预算。1800帧逐帧提交中无脚本异常，80敌节点有界；20轮析构均在最多4.8秒内回到28,288B绘图缓冲/4,221,488B纹理，存储恢复。具体采样和截图在`art/reviews/stability-v913`与`performance-v913.json`；历史v9.12净省22MiB属于上轮成果，不能计为本轮新收益。

最终微信模拟器已核对stage-v9.13-lifecycle，正常首波41次原生onPlay回调、0音频错误、固定6音效源、加载队列清空；console错误筛选无命中。微信主包2.27MiB、总8.71MiB，预览上传统计9,110,715字节，二维码生成成功。CDN版本仍为v95-996129359b44c659。
